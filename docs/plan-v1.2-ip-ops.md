## 1. 定位与边界（铁律）

- AIOS = 受人类控制的「个人 IP 运营与持续改进」系统，**不是**未经授权的自动营销机器人。
- 所有对外动作（发文、发消息、报价、收款、承诺）必须**可审计**且**默认需 owner 批准**。
- 复用现有 AIOS 主线：`Task → Artifact → KnowledgeCandidate → KnowledgeFact`；V4 Agent 中台；WorkLog 知识沉淀；owner 审批与审计原语（参照 #88 WorkLog 的 owner-only 审批边界）。

## 2. 需求 A：个人 IP 内容与变现工作流（MVP）

### 用户旅程
1. **选题**：从市场研究 / 用户问题 / 已沉淀 `KnowledgeFact` 生成选题建议，人工选定。
2. **策划**：基于选题生成大纲 / 角度，人工修订。
3. **内容生产**：生成草稿（图文 / 短视频脚本），落为 `Artifact(type=content_draft)`。
4. **独立审核**：AI 自检合规 / 违禁词 / 事实（复用虾球的违禁词检测能力）。
5. **L4 人工批准**：owner 在控制台一键批准 / 驳回；批准后进入「已审核知识库」可复用。
6. **转化动作**：内容可挂载转化锚点（咨询预约 / 产品页 / 课程 / 模板包），并记录人工复盘数据（曝光 / 咨询 / 转化）。

### 数据边界
- **存**：草稿、审核状态、批准记录、转化锚点、复盘指标（owner 填）。
- **不存 / 不做**：不自动发布到任何平台、不自动承诺效果 / 价格 / 合同、不自动收款。

### 审批规则
- 发布动作**永远 owner 手动触发**（MVP 不做自动发布）。
- 已审核观点 / 案例 / 产品信息 → `KnowledgeFact(series="黎叔AI创业实验室")` 复用。

## 3. 需求 B：客服、答疑与销转（微信 / 企微，MVP）

### 用户旅程
1. **接入**：企微会话 Webhook / API 接入（具体接入方式 owner 后续定；MVP 先用企微客服 API 或中间件）。
2. **会话管理**：消息入 AIOS，建 `Conversation` / `Message` 上下文。
3. **应答建议**：FAQ + 已审核 `KnowledgeFact` 驱动的答复建议（复用 KnowledgeFact 检索）。
4. **升级规则（必须人工）**：命中以下任一 → 转人工 + 留审计：
   - 报价 / 价格
   - 付款 / 收款
   - 任何合同 / 效果 / 交付承诺
   - 投诉 / 纠纷
   - 隐私 / 身份信息
   - 低置信度 / 未知
5. **有限自动发送**：仅「常规问答」（FAQ 命中且置信度高、非升级类）可由 AI 代发；其余必须 owner / 人工在企微侧确认（D3）。
6. **线索与漏斗**：客户 → 意向阶段（`visitor / lead / qualified / proposal / won`）→ 人工接管 → 跟进任务 → 转化。MVP 仅记录阶段，不自动推进。

### 数据边界
- **存**：会话、消息、应答建议、升级事件、线索阶段、跟进任务、审计日志。
- **不自动**：发送报价、收款、客户承诺、超出必要范围保留客户数据。

### 审批规则
- 自动发送**仅限**「常规问答」白名单；报价 / 付款 / 承诺 / 投诉 / 隐私 → **100% 人工**。
- 所有对外发送（含自动）记录审计（who / what / when / which channel）。

## 4. 需求 C：使用反馈 → 产品改进闭环（MVP）

### 用户旅程
1. **入口**：给非技术 owner 一个简单入口（自然语言）：「我需要…… / 这里不好用……」。
2. **记录**：自动存原话、使用场景、期望结果、风险标签、时间 → `Feedback` Artifact（形态复用 WorkLog-like Artifact）。
3. **去重 / 聚类 / 摘要**：周期性（cron）聚类相似反馈，生成清晰摘要与优先级建议。
4. **看板**：收集 → 澄清 → 方案 → 等 owner 批准 → 开发 → 测试 → 已上线。
5. **优先级建议**：基于频率 / 影响 / 风险给建议，但**不得**自动修改生产系统、接入付费服务或改工作流架构。

### 数据边界
- **存**：反馈原文、场景、期望、风险标签、聚类、优先级建议、看板状态。
- **不自动**：改生产、接付费、改架构（仅建议）。

### 审批规则
- 「方案 → 开发」必须 owner 批准（看板 gate）。

---

## 5. 明确不在首个 MVP 实现

- 自动发送（任何渠道的无人审批群发）
- 自动报价 / 自动收款 / 支付对接
- 自动发布内容到公众号 / 小红书等
- 未审批的客户承诺（效果 / 价格 / 合同 / 交付）
- 客服全自动（无人工兜底）
- 跨渠道自动同步客户数据
